# AstraChat 清理审查 · 2026-10-30

## 范围与结论

检查范围为 39 个工具脚本、29 个插件 Python 模块、56 个 Python 测试模块，以及前端源码、样式、依赖和发布文件。核对了静态引用、模块属性访问、框架注册入口、命令行入口及已有测试。

清理前的源码备份保存在本机 `work/cleanup-before-20261030.zip`。账号、模型凭据、运行数据库、用户人设和 helper 源码保留原位。新仓库只纳入发布所需源码、配置样例、说明与测试。

## 已清理与修复

| 项目 | 发现及处理 |
|---|---|
| 不可达模拟控制台 | 当前路由始终进入真实控制台，但 `main.tsx` 仍保留整套模拟上下文、记忆、角色、任务和设置页面。移除不可达页面、模拟状态模块及对应旧测试。 |
| 浏览器持久化 | 原来为主题切换仍反复读写整套模拟数据。改为独立主题设置，首次读取兼容旧主题；不删除旧缓存内容。增加迁移、优先级及损坏缓存回归测试。 |
| 前端无引用代码 | 移除旧详情组件、未使用的导入与变量、`ReferenceKey` 参考面板及无对外使用的类型导出。真实 Key 配置由 `ModelConnection` 继续提供。 |
| 无效样式 | 移除 17 个无页面引用的旧类对应的 32 条选择器；保留动态生成的 `message-user` / `message-assistant` 等类。 |
| Python 无用代码 | 清理 28 个未使用导入、控制台状态中的无用 provider 查询、只写不读的解析计数和旧窗口状态、无引用的常量及旧重连帮助函数。 |
| 间接导出 | `start_wechat_desktop.single_bridge` 被会话管理器通过模块属性调用，必须保留；改为显式重导出，使 lint 能识别其用途。 |
| 初始化导入 | 两个 Hugging Face 缓存常量导入影响语音模型的初始化顺序，保留并说明原因。 |
| 过时测试 | 原始 Compose 样例须去掉后加的微信回环端口才能还原原始指纹；修正样例，不扩大运行时允许清单。启动入口测试改为拦截当前 WebView2 启动器，避免测试意外打开真实窗口。回滚测试显式用 UTF-8 读取中文 JSON。 |
| 过时说明 | 重写首页与配置说明，修正模拟模式、旧模型阶段等失效描述。历史操作笔记、截图和 OpenSpec 记录保留本机，不作为当前发布文档。 |
| 开发依赖 | 旧 Vitest 依赖树报告 1 个中危、2 个严重漏洞；升级至 Vitest 5.0.5 并重新运行前端测试。 |
| 持续检查 | 开启 TypeScript 未使用变量/参数检查，配置 Ruff 检查，增加索引文件发布检查脚本与 GitHub Actions 模板。 |

## 保留的模块和功能

| 分类 | 保留原因 |
|---|---|
| QQ / ClawBot / 桌面微信适配器 | 各自有运行入口和隔离记忆，不能因当前主要使用某一平台而删除其他平台。 |
| 中性回执、中性流式模式 | 仍被配置脚本和插件模式选择调用，用于初始接入与故障诊断。 |
| 旧 Tk / 命令行窗口、后台监督器 | 仍承担显式命令行入口、现存会话生命周期或锁管理；不是整模块死代码。 |
| 桌面与原生探测工具 | 独立 CLI 入口，用于版本、绑定和诊断，未被其他模块导入不代表不可执行。 |
| helper 源码目录 | `work/helper-native-upstream`、`work/helper-native-voice-upstream` 是运行依赖；只排除出 Git，不删除。 |
| 框架钩子、数据类字段 | AstrBot 注册类、事件处理器、HTTP 回调、SQLite 属性及序列化字段由框架或反射调用，保留。 |
| 有意保留的待接入入口 | 搜索/生图模型选择仍仅保存参数；自动摘要、远程角色导入、回退模型及若干灰色参考控件尚未接入。保留明确状态，不作为已完成能力宣传。 |
| 核心兼容与诊断接口 | `eligible`、`can_fallback`、`desktop_stopped` 等仍有测试契约；本轮不删除核心查询接口或扩展自动回退。 |

- 前端 Vitest 5.0.5：6 项通过，TypeScript 未使用变量检查及生产构建通过；另外使用清洁副本重新执行 `npm ci`、测试和构建。

- 首次配置样例可生成运行目录，运行边界检查通过；重复准备返回未新建，保留已有资料。
- 索引文件边界、常见密钥格式、本地敏感配置值比对及发布文档链接检查均通过。CI 模板配置为顺序执行完整后端套件及前端安装、测试、构建。当前发布授权不包含 workflow 权限，模板位于 `docs/ci-checks.yml`，未启用自动运行。

浏览器检查覆盖六个路由在 1440 / 1280 / 1024 / 375 像素宽度下的布局，以及浅色主题、上下文编辑/备份、摘要保存、模型配置和任务弹窗；全部 API 写入由测试拦截，不发送真实消息。只读实时检查确认控制台健康、微信监听连接、QQ / ClawBot / 原生微信服务报告就绪。

## 发布边界与剩余事项

- `.local.json`、环境凭据、数据库、原始角色卡、截图、日志、模型及第三方运行副本不进入 Git；发布检查也对本地配置中的敏感值做了比对，不输出其内容。
- Windows 微信仍需单独配置 helper、客户端版本和账号；语音需独立模型环境。克隆源码后不能直接获得这些本机资产。
- 构建仍提示主 JavaScript 包较大（约 1.35 MB，gzip 约 424 KB），本轮不进行路由拆包重构。
- 离线测试、浏览器合成数据和服务就绪不等于新一轮真实消息送达、语音接收或 24 小时稳定性验收；本轮没有向联系人发送测试消息。
